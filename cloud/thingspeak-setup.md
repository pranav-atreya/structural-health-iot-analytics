# ThingSpeak + MQTT Setup

## Channel fields

Create one ThingSpeak channel with four fields:

1. `vibration_rms` — g
2. `deflection_mm` — mm, relative to unloaded baseline
3. `support_reaction_g` — calibrated g-equivalent at the instrumented support
4. `vehicle_count` — cumulative crossings

## MQTT

- Broker host: `mqtt3.thingspeak.com`
- Use the MQTT client ID, username and password generated by ThingSpeak for the device.
- Publish to: `channels/<CHANNEL_ID>/publish`
- Use the payload format documented by ThingSpeak, e.g. `field1=<value>&field2=<value>&field3=<value>&field4=<value>`.
- Respect the applicable channel update interval (15 seconds for the free service at the time this setup was planned).
- Test with sample values first, clearly marked as test data.

## Credentials

Never commit Wi-Fi passwords, ThingSpeak API keys, MQTT usernames or MQTT passwords. Use a local secrets header/config file excluded by .gitignore, or environment variables. Do not put secrets in screenshots or documentation.

## Integration acceptance test

1. Publish one sample payload using an MQTT test client.
2. Confirm all four fields update in ThingSpeak.
3. Export data and confirm the fields and timestamps are present.
4. Integrate ESP32 messages only after the cloud test works.
